# v5.2.3: SMTP Fix & Auto-Versioning

**Released**: 2026-07-31

## Highlights

Password reset and account emails were silently failing to send for anyone using STARTTLS (`SMTP_TLS=1`), and the app's displayed version no longer needs a manual bump in the Docker Compose files each release.

## Changed

- `APP_VERSION` (the version shown in the UI and `/healthz`) is now auto-derived from `pyproject.toml` at container startup instead of needing a manual bump in `docker-compose.yml`/`dockerhub-docker-compose.yml` each release; those files still accept an explicit `APP_VERSION` override if uncommented, and published DockerHub images continue to get their exact tagged version via `--build-arg`

## Fixed

- Password reset, welcome, and account-created emails (SMTP) always failed with "Connection already using TLS" when `SMTP_TLS=1`/`SMTP_SSL=0`; STARTTLS auto-negotiation is now disabled at the client level so the service's explicit `starttls()` call succeeds, and the real exception is now logged with a traceback instead of being swallowed silently

## Upgrade notes

1. Rebuild the container: `docker compose up --build --no-deps -d web`.
2. No new required environment variables or migrations.
