# v5.4.0: Deprecate JSON Build-Config Workflow

**Released**: 2026-08-02

## Highlights

The saved JSON build-config workflow (web page, REST API, and CLI/Docker file input) has been removed in favor of the existing per-field CLI flags and environment variables, which cover the same use cases with less surface area to maintain.

## Removed

- The saved JSON build-config workflow has been removed: the web `/configs` page, the full CRUD `GET/POST/DELETE /api/v1/configs` REST API, and the CLI/Docker `--config`/`DECK_CONFIG` mechanism (including the auto-export of a `<name>.json` run config after every build). Scripted/headless builds are unaffected: use `headless_runner.py`'s existing per-field CLI flags or `DECK_*` environment variables instead, e.g. `python code/headless_runner.py --commander "..." --primary-choice 1 --add-lands true` in place of `--config config/deck.json`. Existing `.json` config files on disk are left untouched, just no longer discoverable by the app.

## Upgrade notes

1. Rebuild the container: `docker compose up --build --no-deps -d web`.
2. If you scripted builds with `--config`/`DECK_CONFIG`, switch to the equivalent `headless_runner.py` CLI flags or `DECK_*`/`HEADLESS_*` environment variables; see [DOCKER.md](../../DOCKER.md#headless-builds) and the `docs/user_guides/` guides for examples.
3. No new required environment variables or migrations.
