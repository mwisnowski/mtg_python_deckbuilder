# v5.9.0: Scryfall Tagger Integration

**Released**: 2026-08-20

## Highlights

Card search and detail pages now surface two new sources of tags: Scryfall's community Art Tags (describing an illustration, e.g. "blue glow") and the deck builder's own internal Metadata Tags. Both are searchable everywhere existing theme tag search works, including the public API, and search terms with dashes now work the same as their quoted, space-separated equivalent. Tagging quality also gets a round of improvements: new creature type-family groupings, an Oracle Tag adoption workflow, and an editorial fix for commander-eligibility checks.

## Added

- Tagging: new `code/scripts/apply_oracle_tag_adoptions.py` applies human-reviewed Scryfall Oracle Tag consolidation/adoption decisions to `all_cards.parquet`, adding 64 new theme/metadata tags (e.g. Spot Removal, Sacrifice Outlet, Pathway Lands, Group Hug, several Tutor/Theft/Removal/Sacrifice Outlet metadata tags) and merging ~1,800 additional overlap-based tag consolidations across the card pool.
- Tagging: new creature type-family groupings, mirroring the existing Outlaw mechanic: `Party` (Cleric/Rogue/Warrior/Wizard), `Sea Monster` (Kraken/Leviathan/Octopus/Serpent), `Fiend` (Demon/Devil/Imp/Tiefling), `Undead` (Zombie/Skeleton), and `Nature` (Plant/Treefolk/Fungus/Saproling). Cards with a member type now also get the synthetic family type, which surfaces as a `{Family} Kindred` theme tag.
- Data: new optional `artTags` column sourced from Scryfall's community art-illustration tag project, mapped by illustration rather than card function (so different printings of the same card can have different art tags). Buildable on demand from the Setup page ("Art Tags Cache") or via the similarity-cache CI workflow; not required for core deckbuilding.
- Web: new `art:`/`atag:`/`arttag:` search flag (e.g. `art:"blue glow"`) works everywhere the existing `tag:`/`theme:` flag does: the card browser, owned library, manual deck builder search, and the public REST API. Card detail pages show a collapsed "Art Tags" section when an illustration has been tagged, linking back into the new search flag.
- Web: search terms with dashes (e.g. `rabbit-battery`, `t:legendary-creature`, `tag:spot-removal`) now match the same way as their quoted, space-separated equivalent, across card names, types, oracle text, and all tag flags -- no more needing quotes just to search a multi-word value.
- Web: card detail pages show a collapsed "Metadata Tags (internal)" section for the deck builder's own internal/diagnostic tags (bracket markers, token detail, etc.), first time these are surfaced in the UI. New `metadata:`/`mtag:`/`metatag:` search flag lets these be searched the same way as theme/art tags, across the card browser, owned library, manual deck builder search, and the public REST API.
- Public API: card search and card detail responses now include `artTags` and `metadataTags` fields alongside the existing `themeTags`, so clients can display these tags, not just filter by them.

## Changed

- Web: search autocomplete (`GET /cards` theme suggestions) now reads `config/themes/theme_list.json` instead of `theme_catalog.csv`, since the JSON file is regenerated automatically by every tagging run while the CSV needs a separate manual script; new/renamed themes now show up in autocomplete without an extra step.

## Fixed

- Web: fixed a theme catalog path-resolution bug where the search autocomplete's local-dev path calculation could resolve to a small committed test fixture directory instead of the real theme catalog.
- Tagging: `code/scripts/generate_theme_editorial_suggestions.py`'s theme catalog `example_commanders`/`synergy_commanders` suggestions could include cards that aren't actually legal commanders (e.g. Legendary Artifacts/Enchantments/Planeswalkers without "can be your commander" text) as a synergy fallback; now checks real commander-eligibility rules instead of just the word "Legendary" in the type line.
